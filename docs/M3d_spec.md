# NeuroLens — M3d Implementation Spec: brain response

**Builds on:** M1–M3c. The TRIBE v2 model, the GPU run and the architecture stay as they are. What changes is how its output is read and shown. NeuroLens stops selling an "engagement score" and shows a **predicted brain response**: second by second, how strongly an average viewer's brain would respond to the video, relative to typical film and TV viewing. It never claims to predict views, retention or sales.

**Light treatment** (normal review, one real run), except deletion and the worker's write order (a missed key leaves user data behind; a half-written job could publish a result without its brain file): those get tests first by a separate agent and the break-its in §10.

## Decisions (21 Oct)
- **Why the change.** The five old regions detect content (faces, bodies, scenes, social cues, sound), not interest. The old score took the absolute value of each region's mean (so a dip counted as a rise) and stretched every video to 0-1 on its own, so two videos could not be compared. Two outside attempts to predict engagement from TRIBE output failed (r = 0.25 on 24 videos; a null result on 48 in arXiv 2607.01400).
- **Built-in scale.** TRIBE was trained on fMRI responses z-scored per vertex, so its raw output already has a reference: 0 means typical film/TV viewing. Values are shown signed and unscaled.
- **No lag fix.** tribev2 already shifts its predictions 5 s back to cancel the blood-flow delay (its README and demo), so second *t* of the result is second *t* of the video.
- **7 signals in 3 groups**, read from the Glasser areas the TRIBE v2 paper tested (§2), an overall line, a muted (no-audio) copy, summary cards, a 3D brain map, and A-vs-B comparison against the user's own videos.
- **The raw brain output is stored** (with-audio pass), so the map and any later change to the regions need no GPU rerun.
- **No value or persuasion signal**: the model gives no evidence for one.
- **Samples** become open-licensed Blender clips; the 14 third-party samples are removed.
- **One AWS day** deploys M3c and M3d together (§9).

## 1. Scope
### In scope
The new maths (`neurolens/response.py`, replacing `neurolens/engagement.py`); result format 2; the raw brain file; the summary; the brain route; the 410 for old results; S3 CORS; the CSV; config `response`; the page (one-screen layout, player, charts, muted overlay, 3D map with head, compare, wording); the landing page and the app's move to `/app` (§8b); `infra/make_brain_mesh.py`; `infra/make_sample.py`; `deploy_web.sh`; new samples; docs.

### Out of scope
- Linking the response to real audience behaviour (future work in the report, using the consented retention curves M3c collects).
- An ad benchmark library (future work).
- Changes to the model, the GPU passes, billing or the job lifecycle.
- The two notebooks: they carry their own copy of the old maths and never import it, so they keep working as they are.
- Converting old stored results: they expire within 30 days (§4).

## 2. Signals (`neurolens/response.py`)
Areas from the Glasser HCP-MMP1 map (360 areas), the map the TRIBE v2 paper and tribev2's own `get_hcp_labels` use, so each signal reads the area the paper tested (§5.9 and figures 4-5 of arXiv 2605.04326). Vertex order is the left hemisphere (indices 0-10,241) then the right (10,242-20,483), as the model outputs them.

| Signal | Areas | Hemisphere | Group | Why these areas |
|---|---|---|---|---|
| faces | FFC | both | see | paper: face area (FFA) |
| bodies | V4t | both | see | paper: body area (EBA) |
| scenes | PHA1, PHA2, PHA3 | both | see | place area (PPA): the paper's label list omits it; its figure 4 shows it on the medial underside, which is PHA1-3. Our reading, not the paper's words |
| visual | V1, V2, V3 | both | see | early visual cortex (the paper's best-predicted areas for video) |
| sound | A1, LBelt, MBelt, PBelt | both | hear | early auditory cortex (the paper's "Auditory (Early)") |
| speech | A5, STSva, STSvp, 45 | left only | understand | paper's language localiser: A5, STS, Broca's area 45 |
| social | PGi, TE1a | both | understand | paper's emotional-vs-physical-pain contrast: TPJ, MTG |

- **Map files.** `lh.HCPMMP1.annot` and `rh.HCPMMP1.annot` (fsaverage, figshare files 5528816 and 5528819, the copies MNE's `fetch_hcp_mmp_parcellation` downloads). `load_model` downloads them once into `data/hcp_mmp/` (git-ignored, like `data/nilearn/`) and checks their SHA-256 (lh `d4da6346…2b44`, rh `744eff4e…e9a2`, full values as constants in `response.py`); a mismatch or failed download raises, so the worker never runs on a changed map. On AWS they sit with the model weights in `s3://<bucket>/model-data/data/hcp_mmp/` (copied there once by `infra/make_model_data.sh`), so every worker gets them when SageMaker copies the weights in and never depends on figshare; the download is the fallback. They are never committed and never in a Docker image. They are read with `nibabel.freesurfer.read_annot` (installed with nilearn); mne is not needed.
- **fsaverage5.** fsaverage5 is the first 10,242 vertices of each fsaverage hemisphere, so each hemisphere's label array is cut to its first 10,242 entries (as tribev2 does).
- **Licence.** The map is HCP data under the WU-Minn HCP Open Access Data Use Terms: no attempt to identify subjects, redistribution only under the same terms, and the HCP acknowledgement in the report (§11).
- **Exact match.** A name is normalised by dropping the `L_`/`R_` prefix and the `_ROI` suffix (bytes names decoded first); an area matches only when the normalised name equals the target. Every target must exist in both hemispheres' maps: `build_masks` raises `ValueError` naming any that does not. `require_nonempty_masks` stays. Sizes on fsaverage5 (left + right) range from 29 vertices (bodies) upward.
- **Disjoint.** No vertex belongs to two signals.
- **Values.** For each second, the signed mean of the prediction over the signal's vertices: no absolute value, no rescaling.
- **Groups.** see = mean(faces, bodies, scenes, visual); hear = sound; understand = mean(speech, social). **overall** = mean(see, hear, understand). Groups are means of the signal series, not of pooled vertices, so a large region does not outweigh a small one.
- **Series order** (used by the result, the CSV and the page): faces, bodies, scenes, visual, sound, speech, social, see, hear, understand, overall. `SERIES` holds it.
- **Muted.** The same 11 series computed from the no-audio pass, cut to the shared length of the two passes (normally equal).
- **Rounding.** Every value to 3 decimals, computed from the unrounded series.
- `extract_response(preds_full, preds_noaudio, masks)` returns `{format, duration_seconds, signals, muted}` (§3). It is pure numpy.

## 3. Result format 2 (`results/<job_id>.json`)
```
{"format": 2, "duration_seconds": T,
 "signals": {"faces": [T numbers], ..., "overall": [T numbers]},
 "muted":   {"faces": [M numbers], ..., "overall": [M numbers]},
 "job_id": ..., "processing_time_seconds": ..., "gpu"?: ..., "fake_inference"?: true}
```
- T = rows of the with-audio pass; M = min(T, rows of the no-audio pass).
- The `timesteps`/`regions` structure is retired. NaN or infinity still fails the job before anything is published (`put_result`, unchanged).

## 4. Old results
- `owned_result` answers **410 `old_result`** ("This result was made by an older version of NeuroLens. Upload the video again.") for a stored result without `"format": 2`. This covers the JSON, CSV and brain routes.
- The page shows that message in place of the chart. History still lists the job, and per-video delete still works on it.

## 5. Raw brain file (`results/<job_id>.brain`)
- **Content:** the with-audio predictions, float16 little-endian, row-major, shape (T, 20484), no header. A reader gets T from the byte length ÷ (20484 × 2) and rejects a length that does not divide.
- **Size:** about 41 KB per second of video (4.9 MB for the 120 s maximum).
- **Writer:** `storage.put_brain(s3, bucket, job_id, preds)` casts to float16 and raises `ValueError` before writing if any value is not finite after the cast (float16 overflows above 65,504). `storage.brain_bytes(preds)` does the cast and check, so the research copy uses the same bytes.
- **Write order in the worker** (after the `saving_result` claim check, M3c §3b): `put_brain`, then `put_result`. A failed brain write goes down the normal failure path (retry, then refund), and no result is published. A result therefore always has its brain file.
- **Redelivery:** the brain write replaces an earlier copy; `put_result` still never replaces a result. Known limitation: after a redelivery the brain file can come from a later run than the published result. The two differ only by GPU rounding noise.
- **Lifecycle and access:** it sits under `results/`, so the existing 30-day rule and the worker/web IAM already cover it. No Terraform change for this.
- **Research copy:** `storage.put_dataset` gains a `brain` argument (the bytes) and writes `academic/<job_id>/brain`; the video stays under `dataset/<job_id>/`.
- **Deletion:** `storage.job_keys` includes `results/<job_id>.brain`, and `storage.delete_job_prefixes` removes `academic/<job_id>/brain`, so per-video and account delete remove both.

## 5b. Thumbnail (`results/<job_id>.jpg`)
A small still from the user's own video, so History rows can be told apart at a glance.
- **Frame:** the middle of the video (`duration / 2`, from `probe_duration`): opening frames are often black or a title card. 320 px wide, height to keep the aspect ratio, JPEG (`ffmpeg -ss <t> -i <video> -frames:v 1 -vf scale=320:-2 -q:v 5`), about 10-20 KB.
- **Maker:** `inference.make_thumbnail(path, seconds)` returns the JPEG bytes, or raises `ThumbnailFailed` if ffmpeg fails, times out (30 s) or writes nothing. The worker calls it right after `probe_duration`, while the downloaded file is still there.
- **A failed thumbnail never fails the job:** the worker logs it as an error and carries on with no thumbnail; History then shows the placeholder. It is a picture, so refusing a paid analysis over it would be wrong, and the video has already passed `probe_duration`, so a failure here is rare.
- **Writer and order:** `storage.put_thumbnail(s3, bucket, job_id, data)` (`Content-Type: image/jpeg`), after the `saving_result` claim check and before `put_brain`, so a late worker for a refunded job writes none. A failed S3 write raises and goes down the normal failure path, like the brain. A redelivery replaces it.
- **Not in the research copy:** the dataset already holds the whole video.
- **Lifecycle, access, deletion:** under `results/`, so the 30-day rule and the worker, web and Lambda IAM already cover it (no Terraform change). `storage.job_keys` adds `results/<job_id>.jpg`, so per-video delete, account delete, Cancel, the reaper and the dead-letter handler remove it.

## 6. Summary (`results.summarise(result)`)
A pure function, computed by `/api/jobs/<id>/result` at serve time and added to the response as `summary`. It is never stored, so a rule change needs no rerun.

The summary holds only the sound share. The model's first second (t = 0) has no context, so it skips that second unless T = 1.
- **Audio dependence:** over the shared length (from t = 1, like the rest), `1 − Σ max(muted overall, 0) / Σ max(overall, 0)`, clipped to 0-1 and rounded to 2 decimals. It is `null` when the denominator is below 1e-6; the page then says "no strong response to measure".

### Config block `response` (in `config.json`)
`{"colour_range": 0.5}`: the response at which the 3D map's heat colour is full.
- 0.5 is a starting value; the AWS day (§9) checks it against the real sample runs and adjusts it so the map neither stays grey nor saturates.
- `results.validate_response_config` checks that `colour_range` is a number > 0. `create_app` calls it, so a bad block fails at start-up, not on a user's request.
- `/api/limits` adds `colour_range`, so the page can draw the map, signed in or not.

## 7. Web
- **`GET /api/jobs/<id>/result`:** the stored result plus `summary`.
- **`GET /api/jobs/<id>/result.csv`:** columns `t`, the 11 series, then `muted_` plus each of the 11 (`results.COLUMNS`). Muted cells beyond the shared length are empty.
- **`GET /api/jobs/<id>/brain`:** `owned_result` first (ownership, refunded, expired, 410). Then, if `results/<id>.brain` does not exist, 404 `brain_missing`. Otherwise a 302 to a presigned GET for it, valid for 5 minutes.
- **`GET /api/jobs/<id>/thumbnail`:** `owned_job` (another user's job 404). A job that is not `done` → 404 `thumbnail_missing`. Otherwise a 302 to a presigned GET of `results/<id>.jpg`, valid for 5 minutes, sent with `Cache-Control: private, max-age=300` so the browser reuses it while History redraws. No existence check and no result read: History asks once per row, and a missing picture (an old job, a failed thumbnail, an expired result) fails to load in the browser, which then shows the placeholder.
- **`GET /api/jobs/<id>/video`:** the caller's own video, played back on the app page for as long as we still hold it, with no other cap. `owned_result` first (ownership, refunded, expired, 410), so a video plays only next to its result; results expire after 30 days, so a research copy does not keep a video playable beyond that. Then the first key that exists: the upload (`object_key`), or, for a consented job, the dataset copy `dataset/<id>/video<ext>` (`<ext>` from `object_key`, matching `storage.put_dataset`). Answer: 200 JSON `{"url": <presigned GET of that key>, "expires_in": 3600}`. If neither exists, 404 `video_deleted` ("This video has been deleted."). JSON rather than a redirect, so the page can tell a deleted video from a failed load. One hour, not the brain's five minutes: a video is streamed in pieces for as long as it plays, and a viewer may pause and seek later.
- **`POST /api/jobs/<id>/cancel`:** the caller's own job only (`owned_job`, so another user gets 404 before anything else). Only a queued, undispatched job (`verified_duration_ms IS NULL`) can be cancelled; otherwise 409 `not_cancellable` ("This analysis has already started."). `issue_refund(..., "cancelled", queued=True, undispatched_only=True)` re-checks eligibility under the row lock; a refund that returns `False` gives the same 409. After a successful refund, the route deletes `storage.job_keys` (upload, result, brain and thumbnail); it does not delete the research prefixes. A failed delete is logged, the credit stays returned, and the reaper retries failed-job cleanup (M3a §7b). Answer: 200 `{"cancelled": true}`.
- **Uploads are kept 30 days**, like results: the `uploads/` lifecycle rule in `infra/terraform/main.tf` is 30 days (S3 rounds to midnight UTC, so up to 31). A refunded or cancelled job's upload is deleted at once (M3a §7b).
- **Job-active message** (`JOB_ACTIVE_MESSAGE`, the 409 for deleting a job that is still open): "This video is still waiting or being processed. Try again when it finishes."
- **Web role:** `infra/terraform/web_iam.tf` adds `s3:GetObject` on `uploads/*` and `dataset/*` (a presigned URL works only if the signer may read the key; the role boundary already allows it). Applied with Terraform.
- **S3 CORS:** `cors_rule` in `infra/terraform/main.tf` adds `GET`, so the browser can follow the redirect to the bucket.

## 8. App page (`static/app.html`, served at `/app`)
- **Wording:** "engagement" becomes "brain response" everywhere, on the privacy page and the retention guide too. The zero line and every comparison say just "typical" (not "typical TV"). Under the main chart's heading: "Predicted for an average viewer." The consent text is the current upload-dialog wording (M3f §5a): "Share for research and to train NeuroLens's own models ... I own the rights to it."; the privacy page states that models are trained on videos and real audience data, never on NeuroLens's brain predictions.
- **Design goal:** a marketer understands the result at a glance, and the page looks good enough that people walking past a demo stand come over. Meta's TRIBE v2 demo is the inspiration (video and brain side by side, the brain changing as the video plays), not a template. No chart carries more than 2 lines. The prototype that settled this layout is on branch `prototype-m3d-page` (layout D).
- **One screen:** on a laptop (from about 1280 × 720 of browser space; checked at 1470 × 830, a MacBook Air) the whole result fits without scrolling. The page is locked to the window height: the left column holds the player, the right column holds the report, and the brain and the main chart take whatever height is left. Below 860 px wide or 620 px tall it falls back to one scrolling column.
- **Look ("edit suite", look A):** the whole page is dark, like a video editor: background `#0E0F11`, panels `#17181B`, rules `#24262B`, text `#ECEDEF`, secondary text `#B4B9C0`, quiet text `#8A9099`. One font, Geist (Google Fonts, weights 400/500/600). Small corner radii (6 px on buttons and media, 3 px on thumbnails). The heat orange `#FF8A2A` is the only colour: the data (brain, main line), the play button and the selected sample; it is not decoration (the logo is plain text, the upload button white). Charts are drawn for a dark background.
- **Breathing space:** every element earns its place; nothing is repeated (one copyright line, no "click to jump" hints). Actions used now and then sit in a small menu, not in a row of buttons.
- **Uploading:** after Upload, the dialog closes and History shows each row's real progress bar until the file is in. If an upload fails (network error, an S3 refusal, or no progress for 60 s, which aborts it), the row shows "Upload didn't finish…" and the page cancels the job the upload reserved. A job never shows in two places.
- **Running job in History:** a queued or processing job's row shows one status line: the oldest unfinished job, while queued, "Waiting for the GPU" (with "· <N> min" after the first minute; from 15 minutes "· slower than usual"), any other queued job "In line", processing "Analysing · <N> min" (since it was claimed). A freshly uploaded row shows a "Cancel <N>" countdown for its first 15 seconds, then its "⋯" menu returns; the menu's Cancel calls the cancel route (on 200 the row turns into the cancelled row and the balance refreshes; on 409 the list reloads). The page polls the list while any job is open (a failed poll is retried while a job is open), and the row turns into the done (or failed) row by itself; nothing opens on its own. Clicking a running row does nothing.
- **History rows:** clicking a row opens it (a done job with a result). On the right, a small "⋯" button opens a menu whose items follow the job's state: a queued, undispatched job has Cancel; a shared job has Stop sharing; a job with a result has "Download CSV"; a done or failed job has Delete (the server refuses Delete while a job is open). A processing job has no menu (nothing can be done to it). Clicking the menu never opens the row. Opening a done job whose result is refused (401 reloads the page; 403, 404 such as `result_expired`, or 410) shows the server's message and stops polling; only a network error or a 5xx is retried. Delete asks in a page dialog (same look as the other dialogs: "Delete <name>? Its video, analysis and data will be removed.", Delete and Cancel), not the browser's confirm box. The "Add audience retention" link (M3f §5d) stays visible in the row and is also in the "⋯" menu. Each row starts with its video's thumbnail (`GET /api/jobs/<id>/thumbnail`, about 64 px wide) for a done job; a job that is not done, or whose picture fails to load, shows a plain placeholder of the same size, so rows stay aligned. A done job's line gives its upload date and cost; in its last seven days it says "Deleted in <N> days", and after the result has expired, "result expired" (M3f §4 item 5), dates written as "21 Nov 2026". Failure labels are short, each with the existing "not charged" ending: "Not a readable video", "Didn't finish in time", "Failed", "Upload didn't finish", "Video too long", "Not enough credit", "Video replaced after checking", "Processing paused" (M3f §4 item 5); cancelled jobs are not listed.

The scrubber, the video, the brain and every chart's playhead move together (the existing `syncPlayhead`). Every video starts muted (the sound button turns it on); samples start playing on their own, so the stand's screen moves; uploads wait for Play. Clicking the video plays or pauses it, like the Play button. A result opened from History plays its own video from `GET /api/jobs/<id>/video` while we still hold it (the upload for 30 days, or the shared research copy while the result is still available; results expire after 30 days, so the research copy does not guarantee later playback), in sync like an upload; it waits for Play. On 404 `video_deleted` the video area says "This video is no longer available to play. Original uploads are removed after 30 days. See the privacy policy for how long shared research copies are kept.", and play moves the brain through the seconds on its own, at real-time speed. If the video fails to load or stops on an expired link, the page asks the route once more and carries on from the same second; if that fails too, the video area says "This video can't be played here." and the brain plays on its own. (A `.mov` some browsers cannot play ends there too.) A video uploaded in this visit keeps playing from the local file. Brain colours blend smoothly between whole seconds (linear between the two neighbouring seconds), so the map flows instead of jumping.
- **Top bar:** the logo (to `/`) and the header line, then, signed in: the credit, the email as a button that opens a small menu ("Sign out", "Delete account"), and the white "Upload a video" (opens the upload dialog). Signed out: only a white "Sign in" (to `/login`). No other navigation buttons. During start-up, until `GET /api/me` answers, none of these show, and the chooser shows only the start-up panel, so it never flashes the signed-out view before the signed-in one. - **Chooser (left column while no video is open):** signed in, the upload box, the no-credit note, then the list of past jobs ("No analyses yet." when there are none); signed out, the Sign in box. The samples show in the empty report area (right). The privacy link stays at the column's foot.
- **Report (right column), top to bottom:**
  - The sound share is one quiet line beside "Show if muted": "<N>% of the response comes from the sound".
  - The "Add audience retention" link (done, shared uploads; it opens the pop-up of M3f §5d) sits at the bottom of the player column, under the timeline. The top bar does not repeat the clip name (the player shows it).
  - **Main chart:** heading, then "Predicted for an average viewer." The overall line, with a dashed zero line.   - **Sizing:** the main chart and the strips share the leftover height so the strips stay readable (roughly main chart 55%, strips 45%); the main chart never takes most of the column.

Clicking any chart seeks.
- **3D brain:**
  - three.js plus OrbitControls, vendored at one pinned release (like `static/chart.min.js`).
  - The mesh is `static/brain/fsaverage6_pial.bin` (committed), made once by `infra/make_brain_mesh.py`: the folded (pial) surface at fsaverage6 detail, so it looks like a real brain. The model's values exist only at the 20484 fsaverage5 points; fsaverage6 is fsaverage5 with each triangle split once, so every fsaverage6 vertex is either an fsaverage5 point or the midpoint of an edge between two of them. The script finds each vertex's two fsaverage5 parents (equal for an fsaverage5 point) from the sphere surfaces and checks the nesting (fsaverage5 points match exactly; each midpoint is equidistant from its parents); the page colours a vertex by the mean of its parents' values. Layout, little-endian: uint32 vertex count V, uint32 face count F, float32 xyz × V, uint32 × 3 × F, uint8 × V (1 = no cortex: Destrieux `Medial_wall` or `Unknown`, mapped from the parents), float32 × V (sulcal depth, scaled to -1..1, for the fold shading), uint32 × 2 × V (parents). The file is about 4 MB, downloaded once and cached. The script fetches fsaverage6 through nilearn once (a public download) and stops if it cannot.
  - The brain panel fills the rest of the left column (no height cap).
  - Look: white brain (folds shaded: ridges white, grooves light grey) on a near-black panel, like Meta's demo, a three-quarter front view, slowly orbitable (no zoom; the view fits the panel). A hot scale like Meta's (dark red, red, orange, yellow, pale yellow-white at the top, so a strong spot glows from red edges to a bright centre instead of flattening into one colour) shows only above-typical response, so hotter always means stronger; it fades in from the white near 0 and is full at `colour_range`. Below-typical stays white (the charts show it). No-cortex vertices are a soft grey.
  - A faint see-through head around the brain (edges glow, the face is clear): `static/brain/head.bin` (same header and float32 xyz and face layout as the mesh, nothing after the faces), made by the same script as the outer surface of the MNI152 2009 template that ships inside nilearn (no download). Its licence (permissive, keep the copyright notice) is checked before use and the notice goes in `static/brain/LICENSE.txt`. Meta's assets are not reused (no licence).
  - The brain file is decoded with a small float16 decoder. If it is missing or malformed, the panel says the 3D view is not available for this video; the rest of the page works.
- **Compare:** "Compare with…" picks another done job, or another sample when the open video is a sample. The Compare tab is the only place a comparison shows: the two videos side by side, each title in its line's colour with its average overall in words ("above typical on average", the number in a tooltip), then the overall chart on the longer time axis and one row per difference with coloured dots and each span's times ("0:00–0:06", plus "only" when just one side has it). The comparison and its states ("Write comparison", "Writing your comparison…", failure with "Try again"), the verdict and the "Where <name> does better" lists and "Suggestions" all live in this tab; when there is no comparison report and none can be written (a sample pair without a stored comparison, or the user's video against a sample), the verdict aside is hidden and the chart takes the full width. A "Close" button returns to Analysis and pauses the second video. Analysis and the Report tab stay single-video. A "Swap" button opens the other job as this one (its player, brain and history tab) and compares it with the video that was open; it shows only for the user's own jobs, since only jobs can be swapped. Choosing a comparison does not change "Show if muted". Signed-out visitors see Compare only for samples.
- **Long file names** are shortened in the middle to about 32 characters, keeping the start and the end with the extension ("my_long_campaign…final_v3.mp4"), with the full name on hover, wherever a file name is shown: History rows, the player title (an upload's file name without its extension; a sample's title), the chart legend, the compare picker, and the "<name> ends" label (a chart label has no hover). Samples are named by their title, not their video file path; the two compare titles show the full name and wrap.
- **Samples** render like a job result, and show their attribution line once, under the video (CC BY requires it).

## 8b. Landing page (`static/index.html`) and the app at `/app` (`static/app.html`)
- **Why:** visitors who are not signed in (interviewers, people at the demo stand) need to see what NeuroLens does before signing in. The prototype that settled this is on branch `prototype-landing` (layout A).
- **Routes:** the landing page is the front page: `static/index.html`, served at `/` (Flask locally; on AWS it is CloudFront's `index.html` as today). The app page moves unchanged from `static/index.html` to `static/app.html`, served at `/app` (Flask route; on AWS `deploy_web.sh` uploads it to the key `site/app` with `Content-Type: text/html; charset=utf-8` and `Cache-Control: no-cache`, like the front page). `/app` is public, like `/`. After sign-in, `/auth/callback` redirects to `/app`. Sign-out still returns to `/`, which is now the landing page. The app's logo links to `/`.
- **Signed-out visitors at `/app`** (from "Explore samples") see only what they can use (§8 Top bar and Chooser).
- **Signed-in visitors at `/`:** the landing page is a static file (CloudFront), so no server sees the visit. Sign-in also sets a hint cookie, `nl_signed_in=1` (not HttpOnly, so the page can read it; same `Secure` and `SameSite=Lax` as the session; path `/`; max-age the session's 30 days, the same sliding lifetime as the server session in M3f §6b). It carries no identity and grants nothing: it only picks which buttons show. `POST /logout`, account deletion and a session refused for a deleted account delete it. A small inline script in the landing page's `<head>` reads it before the page is drawn: if set, the top bar's Sign in becomes "Open NeuroLens" (to `/app`), the hero's and the closing band's sign-in buttons become "Upload a video" (to `/app?upload=1`, the hero's white), and every "Explore samples" button is hidden. "Open NeuroLens" just opens the app; `upload=1` makes the app show its upload box once signed in, then the app removes the parameter with `history.replaceState`, so a reload or Back does not reopen it. No `/api/me` call and no jump. A stale hint (session expired) shows "Open NeuroLens"; the app then shows the Sign in box and deletes the hint. No automatic redirect. Laptop mode is always signed in as the dev user: its `/` sets the hint and its `/login` just redirects to `/app`.
- **Layout (A, one column of sections):**

## 10. Tests
Existing tests that pin the old format (`timesteps`, `regions`, `engagement_overall`, the 0-1 rescale) are **rewritten** to format 2. This is the intended change this spec approves, not editing tests to make them pass. The old golden file `tests/fixtures/extract_engagement_golden.json` is **replaced** by `extract_response_golden.json`, regenerated from the new code.
- **Masks:** name normalisation (`L_FFC_ROI` matches `FFC`); exact names (a near-miss does not match; an area missing from either hemisphere raises); the cut to 10,242 vertices per hemisphere; speech only on left vertices; no overlap; none empty. Tests build a small synthetic annot file and make no network call; a wrong SHA-256 raises.
- **Values:** signed means with no rescaling (a region with negative predictions gives negative values); groups and overall from the signal series; the muted length cut; 3-decimal rounding; series order.
- **`summarise`:** only the audio dependence is returned; the ratio, the null cases (no positive response, denominator below the floor), clipping to 0-1 and rounding to 2 decimals.
- **Config:** `validate_response_config` refuses a missing, non-numeric or non-positive `colour_range`; `create_app` refuses a bad block.
- **CSV:** the column list; empty muted cells beyond the shared length.
- **Web:** 410 for an old result on the JSON, CSV and brain routes; the brain route's ownership (another user gets 404, a refunded job gets 404), `brain_missing`, and the 302 to a presigned URL for the right key.
- **Video route (full: ownership):** another user's job gets 404 and no presign; a refunded job 404; an old result 410; upload present → `url` presigns the upload key with `expires_in` 3600; upload gone, consented, dataset copy present → the dataset key (keeping a `.mov` extension); upload gone and not consented (even if a stray dataset copy exists) → 404 `video_deleted`; nothing left → 404 `video_deleted`.
- **Cancel route (full: money):** another user's job 404 and nothing changes; an undispatched queued job is refunded once (`cancelled`, balance back, one refund ledger row) and its own file keys deleted (moto); a dispatched queued job is refused; a second cancel is 409 with no second refund; a `processing`, `done` or `failed` job is 409 and nothing changes; claim then cancel → 409, job still processing; cancel then claim → claim returns `None`; a failed upload delete still answers 200 with the credit back.
- **Deletion (full):** `storage.job_keys` includes `results/<job_id>.brain`; `storage.delete_job_prefixes` removes `academic/<job_id>/brain`; per-video and account delete remove both (moto).
- **Thumbnail (full: deletion and ownership):** `make_thumbnail` on a tiny real clip returns JPEG bytes 320 px wide and raises `ThumbnailFailed` on a non-video; the worker writes `results/<id>.jpg` for a done job (fake mode), after the claim check (a refunded job gets none) and not into `dataset/`; a failed `make_thumbnail` still finishes and charges the job, with no thumbnail; `storage.job_keys` includes it, and per-video delete, account delete and Cancel remove it (moto; the reaper and dead-letter handler use the same `job_keys`, already tested); the route gives another user 404 with no presign, a queued, processing or failed job 404 `thumbnail_missing`, and a done job a 302 to the presigned key with the cache header.
- **Worker (full):** the brain is written before the result; a failed brain write publishes no result and goes down the failure path; a non-finite value (or a float16 overflow) is refused before any write; a consented job writes `academic/<job_id>/brain` with the same bytes.
- **Samples:** `test_samples_schema` checks the new entry shape and that every sample's brain file length divides by 20484 × 2.
- **Mesh:** the committed mesh file parses: header counts match the length, face indices in range, both parent indices of every vertex are < 20484, and exactly 20484 vertices are their own parent (the fsaverage5 points).
- **Landing (light):** `/app` serves `static/app.html` and is public (signed out, Cognito mode); `/` still serves `static/index.html`; `/auth/callback` redirects to `/app`. The public-routes test adds `/app` to its list (Josh approved, 22 Oct). The page itself is checked by a walk, not unit tests.
- **Break-its** (on committed code): drop a brain key or the thumbnail key from `storage.job_keys`, remove the ownership check from the thumbnail route, remove the ownership check from the brain route, and remove it from the video route; let the cancel route refund a `processing` job (`processing_stale_s=0`), and drop the reaper's `created_at` deadline. A test must fail each time.
